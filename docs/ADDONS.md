## Policy implemented for shadow replay

`src/participation.ts` is independent of the existing explicit-request core. An owner with the configured approver ID/role can select shadow mode. Default remains off. Three moves are supported: constraint reminder (`forgotten_constraint`), clarification (`uncertainty`, `underspecified_plan`) and loop breaking (`discussion_loop`). Other proposed breakdown names are recognized but withheld as unimplemented. Catch-up stays a direct request.

Monitor and repair are independent typed observations. Code requires three distinct observations of the same normalized claim with unchanged evidence, confidence at least 0.85, valid source identities, allowed scope/settings and no participant repair, outstanding invitation, prior intervention or cooldown. These are our conservative development defaults, not reported optimal parameters or copied speech thresholds. Claim matching is normalized exact text; no embedding model is used. A gap longer than ten minutes resets persistence. A resolved or already-said claim stays suppressed in this experimental ledger until it is purged; handling a later recurrence needs a new evaluated design.

The repair observation must point to an exact quotation in the last three authorized messages. This rejects invented references; it does not prove the quotation semantically resolves the claim. Likewise, resolving a citation proves source identity/availability, not entailment. Both require actual model evaluation and human checking.

Default hand raising records an offer for ten minutes without generation. Only a configured member's explicit reply/action with the exact offer token and triggering-message binding permits generation. Ordinary agreement, unrelated replies and cross-room actions do not. The shadow direct mode can instead generate an intent immediately after the gate; neither mode can send a real message. Generated text is limited to two sentences and 240 characters; citations are appended by code. Recheck scope, pause, settings, source/trigger identity and changed conversation before returning the intent. Invitation retries and uncertain generation do not produce automatic retries.

The experimental SQLite ledger is separate from the existing service database. It persists short claim names, counts, bindings, offers, deduplication and reasons, without full chat windows, generated responses or media bytes. `why()` returns scoped metadata. `purge()` removes its scoped content/settings and compacts the database. The local conversation now composes this policy with media, watch tasks, normal requests and explicit deletion across the stores; see LOCAL_HARNESS.md. It remains outside the live lifecycle, designed for one process; multiprocess load/delivery is unverified.

## Local error watch

Run `npm.cmd run conversation:offline`, then `/watch start`, `/watch tick` three times, and `/watch stop`. Each terminal tick advances a simulated minute; it does not wait or poll Roblox. The frames produce a new synthetic error at count 2, silence at unchanged count 2, then an increase to 5. Reports cite the stored observation and the actual selected party-route.ts line 3. Missing source/line yields explicit uncertainty, never an invented cause. These deterministic reports do not claim Meta diagnosed the error.

Creation/stopping requires the configured simulated approver. The task captures project/platform/workspace/room, selected snapshot, universe ID, interval and configuration identity. One active watch per project prevents accidental overlap. Calls before the next interval do not read a feed; changed configuration or pause blocks reporting. Stop also works while paused. Baselines survive restart in ignored watch-replay.sqlite. Compare increases only within the same counting window; changing windows establishes a baseline for known groups. A decrease in the same cumulative window is invalid. Unknown fields are stripped and obvious secret assignments rejected before evidence storage; ingress accepts synthetic replay only.

For automatic local operation, use `/watch start`, `/watch auto on`, then leave the terminal open. The scheduler follows the task's real interval, at least one minute, and prints only changed reports. `/watch auto off` retains the task for manual use; `/watch stop` deactivates it. Pause, explicit data deletion and host exit stop the scheduler. It does not resume automatically on application restart; the owner must enable it again. Synthetic feed progress is now derived from a persisted poll sequence, not a new process's private counter. Existing older replay tasks may need an explicit stop/start rather than guessing their missing sequence.

Reads receive an AbortSignal and are bounded to 30 seconds. Cancellation discards late results even if a feed fails to cooperate; a future network feed must honor that signal to terminate its own request. No source or baseline from a stopped/purged in-flight task is retained. Immediately before local console dispatch, the scheduler rechecks active task, configuration, poll sequence and exact source identities. Delivery callbacks are synchronous local observers; no remote messaging adapter is present. Failed reads stop automatic scheduling without repeated attempts; an owner may explicitly enable a later attempt.

`npm.cmd run watch:timed-demo` runs a roughly two-minute offline process using the actual production minute interval and Node's native 30-second timeout. Evidence/watch-timers-v1.json records the observed outputs and source/built-file identities. Observed: count 2 at 13.9 ms, unchanged silence at 60,022.2 ms, count 5 at 120,031.1 ms, with a separate nonresponding synthetic feed stopped at 30,014.7 ms after one attempt. No model/service request or external post. This process check is separate from fast mocked-clock unit tests and is not repeated in CI.

ErrorWatch.purge erases its task/baseline store; Store.purgeProject erases imported observations and preserves charges. The local explicit deletion flow cancels scheduling and invokes both plus participation deletion, pausing before store deletion and retaining the paused state if one part fails. No repository write, arbitrary source path access, rule mutation or real API call occurs. A verified live read-only collector remains future integration.

## Media pipeline and prepared adapter

MediaPipeline accepts authorized supplied bytes, binds derived text to the original message/version and selected snapshot, deduplicates, and rechecks access/pause/source availability after derivation. Source removal erases derived text and invalidates saved evidence; it works while paused. The canonical path is in memory. Optional attachment preparation stages one owned temporary input, deletes it before derivation and rechecks scope/source after conversion; see [CODECS.md](CODECS.md) for handling and crash limitations. Caller buffers remain unchanged; the pipeline clears its own copy after use. Derived text is a labelled observational source, without automatic log-window expiry, subject to explicit revocation and project purge. It is untrusted content, never approval or executable instructions.

The canonical boundary accepts mono PCM16 WAV at 16/24 kHz up to ten minutes, PNG/JPEG up to 2 MB, and MP4 up to 8 MB with adapter-verified duration at most 30 seconds. Its header checks alone are not full decoding. The optional fixed FFmpeg normalizer converts OGG/Opus/WAV, decodes images and verifies actual clip duration; no caller URL/path/command is accepted. Four real codec fixtures and two rejection cases passed with MOCK derivation, zero model requests. Discord acquisition remains deferred; no shell/downloader is exposed. Non-synthetic media requires verified private handling at ingress; account terms/entitlement remain untested.

MetaMediaProvider implements recording multipart transcription, inline image understanding, and video upload with purpose user_data followed by Responses and deletion of that exact upload. Models: Spark 1.3 Standard for images/silent video, 1.2 Standard only when the caller explicitly marks clip sound important, Voice Transcribe for WAV. This is an explicit choice, not automatic fallback. Fixed synthetic testing routes now exercise it through Infisical; no product/Discord route is connected. Mocks verify fields, limits, usage, no retries, uncertain reservations and cleanup. Failed/uncertain uploads retain metadata and prevent another video upload until cleanup is reviewed; unrelated files are never deleted. A successful DELETE response is a service acknowledgement, not independent storage-erasure proof.

Audio reserves bounded duration and records reported processed time. A real receipt exposed 20-ms processing-frame rounding; the adapter bounds it to the next frame, still at most ten minutes, and reserves that ceiling. Larger reports still fail. Visual requests reserve full documented Spark context capacity plus bounded output (2048 tokens; 4000 for explicitly audio-important clips), then settle reported usage. All use the existing charge ledger, capped at USD 5. createMetaRuntime composes direct answers, participation and media with one shared transport held through the complete bounded response body. A host must use one such runtime and the existing exclusive state lock.

The actual five-case v1 pilot failed 3/5 and is preserved. V2 regenerated the same fixture recipe after the observed fixes: real ASR, two image cases and a silent video transition satisfy their predefined facts and authorized source/revocation checks. The audio-important clip recovered the speech but described its provenance inconsistently, so it is partial and uncredited despite passing literal patterns. Thus v2 meets the four-of-five synthetic regression target, not a fresh held-out/human/general media benchmark. Four video uploads across both runs were acknowledged deleted; raw fixtures and each own project were removed, charges preserved. See LIVE_TESTS.md and the separate v1/v2 review records. No transcript/expected answer was supplied to the model as a substitute for media.

## Sources checked and future integration details

[Jarvis](https://arxiv.org/html/2610.07506) motivates separate monitoring, repair, a ledger/gate and grounded generation. Its published results concern its own speech system, corpus and study; they do not measure this application. [ProACT](https://arxiv.org/pdf/2607.03730) informs breakdown categories and concise group-facing contributions. We reuse these design ideas with attribution; no paper code, dataset or prompts have been imported.

Official [Meta speech documentation](https://dev.meta.ai/docs/speech-to-text), checked 29 October, describes recording transcription at `/v1/asr/transcribe`, model `muse-voice-transcribe-1.0`, multipart `request` and `audio`, mono 16-bit PCM WAV at 16/24 kHz, maximum ten minutes/32 MB. It lists $0.18 per processed audio hour. Account entitlement and privacy requirements must be checked before enabling it.

Official [video/audio documentation](https://dev.meta.ai/docs/video-understanding) supports uploaded video references and warns that Muse Spark 1.3 audio quality is degraded, using 1.2 in audio examples. Future media handling must use verified current schemas, bounded input and temporary storage with deletion, authorized attachment sources and Standard mode. Derived text retains the original message reference and remains untrusted evidence. No automatic fallback to another model is enabled.

Official [image](https://dev.meta.ai/docs/image-understanding), [file handling](https://dev.meta.ai/docs/file-handling), [models](https://dev.meta.ai/docs/models) and [pricing](https://dev.meta.ai/docs/pricing-rate-limits) docs were also checked. Uploads do not expire by default. Published Spark context capacity is 1,048,576 tokens and Standard input/output rates are $1.25/$4.25 per million tokens. These are documented limits/rates, not measured account charges.

Official [Roblox error reporting](https://create.roblox.com/docs/cloud/guides/error-reporting) requires read analytics scope plus the key owner's analytics access. Discovery uses the ErrorCount metric by MessageHash; error details use the documented GET path. That is more than a single guessed polling URL. No rule writes, arbitrary URLs, production-key access or live collector has been added. A sanitized saved-JSON replay is the first useful local watch slice.
