# Participation model shadow pilot v1

This is a new self-authored synthetic engineering replay, not a user study, an independent held-out benchmark or the older mocked development corpus. Runtime/prompt/configuration hashes were frozen and committed before this corpus was authored. There are 40 labelled final decision moments across 180 turns: 15 should speak (five constraint reminders, five clarifications, five loop breakers), 15 matched self-repairs that should stay silent, and ten six-message quiet exchanges. The same speakers do not contradict a personal availability statement in the positive scheduling example; that development-data error is not reused.

`cases.jsonl` contains supplied conversation/evidence only; `labels.json` is grader data. The runtime projection picks only authenticated synthetic scope/actor IDs, message text/version, reply metadata and simulated timestamps. It excludes case/pair IDs, labels, ideal actions and arbitrary added fields. Approved constraints are explicitly seeded through the store with a simulated permitted actor; they are not inferred from casual conversation and are not live human approvals. The grader file is parsed only after model work completes/stops.

`npm.cmd run test:participation-live` is a fixed Infisical test route, separate from CI and the MOCK terminal. It requires the existing key/session and the shared locked charge ledger. At most 440 sequential inference requests are possible: two independent observations per ordinary message, plus at most one bound simulated invitation per case with a repair/generation pair. The native reasoner/shared transport serializes actual requests; these are logical independent observations, not simultaneous paid calls. All requests reserve within the cumulative USD 5 ceiling (or a stricter configured limit). HTTP/budget failure stops after draining the current observations, retains uncertain charges and marks remaining work NOT_RUN; it does not retry.

The policy is evaluated unchanged: persistence 3, confidence 0.85, exact normalized claim match, stable evidence identities, cooldown/dedup and default hand raising. The provider uses Muse Spark 1.3 Standard, 2048 maximum output/reasoning tokens and unset sampling defaults. This differs from the draft's low-temperature suggestion: current [Meta documentation](https://dev.meta.ai/docs/protocols/responses) recommends defaults and clear instructions for Spark. Output is JSON prompted and schema-validated; no server-side JSON-schema mode is claimed.

For each case the harness feeds one message at a time through actual monitor, self-repair and policy code. It records observed wall latency separately from replay timestamps. After the conversation finishes, an outstanding offer may receive a bound invitation from a simulated member, regardless of its grader label. Generated POST is a shadow intent only; there is no Discord/reaction/message transport. Pure ID resolution is recorded separately from semantic evidence support. Claims/settings/reasons and seeded project content are purged from the temporary in-memory stores; durable charges remain. Private model observations/generated text stay in ignored `.local/evidence/participation-pilot-v1.json`; no invitation token is published.

The predefined action targets are at least 9/15 final catches, no more than 3/25 negative-case interruptions and at least 3/5 catches for each move. An early offer is not credited as the labelled final catch and counts as an interruption on its repaired twin. Missing/blocked cases cannot become correct silence. Invalid model-output counts are reported separately; silence caused by unavailable output is not evidence of semantic judgment. Action thresholds alone do not pass semantic correctness/helpfulness or 20 manual judgments. A pass remains shadow-only pending those checks. If the action pilot fails, retain the numbers and ship mention-only as specified; do not repeatedly retune this corpus to obtain a green score.

The first-attempt capture is never overwritten. Corpus authoring refuses regeneration. A subsequent different experiment requires its own version and the same cumulative budget; completed cases are not silently replayed.
